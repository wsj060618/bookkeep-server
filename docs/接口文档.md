# 班费记账系统 · 接口文档

> 后端：Spring Boot 3.3 + MyBatis-Plus + MySQL 8 + JWT
> 前端：Vue 3 + TypeScript + Vite + Element Plus（同源，Nginx 反代 `/api`）
> 本文档覆盖已实现的 16 个接口，可直接用于前端开发与联调验收。

## 通用说明

### 基本信息

服务地址（本地）：`http://localhost:8080`

接口前缀：`/api`

数据格式：`application/json`（导出接口返回文件流，见 3.6）

字符编码：`UTF-8`

### 认证方式

登录成功后服务端下发 JWT 令牌，之后每次请求都要在请求头携带：

```
Authorization: Bearer <token>
```

以下 3 个接口**无需登录**：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/register` | 注册 |
| POST | `/api/auth/login` | 登录 |
| GET | `/api/public/report/{shareToken}` | 只读公示页 |

其余接口一律需要登录。未登录或 token 失效返回**真实 401**，响应体仍是下面的统一结构。

### 统一响应结构

| 字段 | 类型 | 说明 |
|---|---|---|
| code | number | 业务状态码，`200` 表示成功 |
| message | string | 提示信息，成功时为 `success` |
| data | any | 业务数据；无返回值时为 `null` |

### 状态码与错误处理（重点）

| 场景 | HTTP 状态码 | body.code |
|---|---|---|
| 成功 | 200 | 200 |
| 参数错误 / 业务错误（余额不足、用户名已存在、月份格式错…） | **200** | 400 / 404 等语义值 |
| 未登录、token 失效 | **401** | 401 |
| 已登录但无权限 | **403** | 403 |
| 资源不存在（含接口路径不存在） | 200 | 404 |
| 服务器异常 | 200 | 500 |

结论：**前端不能只看 HTTP 状态码**。

- 业务错误：HTTP 仍是 200，必须读 `body.code`；
- 只有认证/授权失败才是真实的 401/403；
- 收到 `code=401`（含 HTTP 401）→ 清 token、跳登录页；
- 收到 `code=403` → 提示「无权限」。

错误响应样例：

```JSON
{
  "code": 400,
  "message": "班费余额不足，当前余额 100.00",
  "data": null
}
```

### 金额与日期约定

| 类型 | 格式 | 示例 |
|---|---|---|
| 金额 | 字符串，固定两位小数 | `"620.00"`、`"1280.00"` |
| 日期 | `yyyy-MM-dd` | `"2026-09-05"` |
| 月份 | `yyyy-MM` | `"2026-10"` |

金额一律是**字符串**：JS 的 number 是双精度浮点，`0.1 + 0.2 !== 0.3`，前端不要 `parseFloat` 后累加，直接展示或交给 decimal 库计算。

### 分页约定

| 项 | 值 |
|---|---|
| 入参 | `page`（从 1 开始，默认 1）、`size`（1–100，默认 10） |
| 出参 | `data: { total, list }` |

字段名固定为 `total` / `list`，不是 `records` / `rows`；页码参数是 `page`，不是 `current`。

### 数据隔离

前端**永远不要传 `book_id` / `userId`**。后端从登录用户的 `current_book_id` 推导当前账本，所有查询都带账本归属校验。用别人的分类 id 或流水 id 操作，一律按「不存在」处理（404）。

## 认证

### 注册

#### 基本信息

请求路径：`/api/auth/register`

请求方式：`POST`

接口描述：该接口用于注册账号。注册成功即创建班级账本（`type=class`），并预置 11 条班级分类（7 条支出 + 4 条收入，见附录 B）

#### 请求参数

参数格式：`application/json`

参数说明：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| username | string | 是 | 显示名：≤20 位，字符不限（登录用邮箱，不用它）；可在账号设置里修改 |
| password | string | 是 | 6–32 位，字母/数字/下划线至少含两种，落库前 BCrypt 加密 |
| email | string | **是** | ≤100 字符，须符合邮箱格式（ASCII 本地部分 + 带点的域名，顶级域 ≥2 位；`123@qq`、`张三@qq.com` 一律 400）。**登录凭据**：全局唯一（未删除行内），也是找回密码的通道 |
| bookName | string | 否 | ≤50 字符；不填默认「班级账本」 |

请求数据样例：

```JSON
{
  "username": "生活委员",
  "password": "abc123456",
  "email": "life@example.com",
  "bookName": "计科2301 班费"
}
```

#### 响应数据

参数格式：`application/json`

参数说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| data.id | number | 用户 id |
| data.username | string | 显示名 |
| data.email | string | 登录邮箱 |
| data.avatar | string | 头像 URL，当前版本恒为 null（功能未开放） |
| data.currentBookId | number | 当前账本 id |

响应数据样例：

```JSON
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1,
    "username": "生活委员",
    "email": "life@example.com",
    "avatar": null,
    "currentBookId": 1
  }
}
```

#### 备注说明

> 注册接口**非幂等**：同一用户名/邮箱连点两次，第一笔成功、第二笔返回 `400 用户名已存在` 或 `400 邮箱已被注册`。
> 前端必须做按钮单飞（`submitting` 标志 + `finally` 复位），并在收到「已被占用」时引导「去登录」，而不是提示「注册失败」——那多半是自己上一次点击已经成功。
> 该接口不返回 token，注册成功后需要调用登录接口（用**邮箱**登录）。

### 登录

#### 基本信息

请求路径：`/api/auth/login`

请求方式：`POST`

接口描述：该接口用于登录班费记账系统，登录成功后下发 JWT 令牌

#### 请求参数

参数格式：`application/json`

参数说明：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| email | string | 是 | **登录凭据**：注册时填的邮箱（比较不区分大小写） |
| password | string | 是 | 明文密码，仅用于与库中 BCrypt 哈希比对 |

请求数据样例：

```JSON
{
  "email": "life@example.com",
  "password": "abc123456"
}
```

#### 响应数据

参数格式：`application/json`

参数说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| data.token | string | JWT，之后放进 `Authorization: Bearer <token>` |
| data.user | object | 用户信息，结构同注册接口的 `data` |
| data.books | array | 该用户的账本列表 |
| data.books[].id | number | 账本 id |
| data.books[].name | string | 账本名 |
| data.books[].type | string | 账本类型，当前固定 `class` |
| data.books[].shareToken | string \| null | 当前公示链接的 token（32 位）；**从未分享过为 `null`**，链接 3 天有效 |
| data.books[].shareTokenExpiresAt | string \| null | 链接到期时间 `yyyy-MM-dd HH:mm:ss`；`null` 或已过期表示没有可用链接 |
| data.books[].categoryTemplateId | number \| null | 当前分类来自哪套自定义模板；**`null` = 内置「班级班费」模板**（内置模板 id 为 0，不入库） |
| data.books[].semesterEnd | string \| null | 学期截止日期 `yyyy-MM-dd`；`null` = 没填（只展示，不参与统计） |
| data.books[].archived | boolean | 学期归档：`true` = 只读（不能记流水 / 不能改分类，仍可改名、改截止日期、取消归档、导出、公示） |
| data.books[].current | boolean | 是否为当前账本 |

响应数据样例：

```JSON
{
  "code": 200,
  "message": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxIn0.xxxx",
    "user": {
      "id": 1,
      "username": "生活委员",
      "email": "life@example.com",
      "avatar": null,
      "currentBookId": 1
    },
    "books": [
      {
        "id": 1,
        "name": "计科2301 班费",
        "type": "class",
        "shareToken": null,
        "shareTokenExpiresAt": null,
        "categoryTemplateId": null,
        "semesterEnd": "2027-01-15",
        "archived": false,
        "current": true
      }
    ]
  }
}
```

#### 备注说明

> `books` 平铺在 `data` 下（不是 `data.user.books`）。当前虽然只有一本账本，字段保留是为了前端以后不用改结构。
> 邮箱不存在与密码错误返回**同一句**「邮箱或密码错误」，接口不暴露账号是否存在，前端也不要区分这两种情况。
> token 建议存 localStorage，过期时间 7 天；收到 `code=401` 时清 token 并跳登录页。

### 忘记密码

#### 基本信息

请求路径：`/api/auth/forgot-password`

请求方式：`POST`

接口描述：申请重置邮件；填**注册邮箱**（它就是登录凭据），已注册才会真的发信

#### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| email | string | 是 | 注册时填的邮箱（登录凭据）；格式同上，不合法返回 `400 邮箱格式不正确` |

```JSON
{ "email": "life@example.com" }
```

#### 响应数据

`data` 为 `null`，**永远返回 `code=200`**。

#### 备注说明

> 邮箱未注册、被限流（同邮箱 3 次/小时、同 IP 10 次/小时）、SMTP 未配置，响应都完全一样：
> 前端只展示「如果该邮箱已注册，重置邮件已经发出」。**不要**用它判断账号是否存在。
> 邮件里链接 15 分钟有效、只能用一次；重新申请会让旧链接立刻失效。

### 重置密码（凭邮件 token）

#### 基本信息

请求路径：`/api/auth/reset-password`

请求方式：`POST`

接口描述：用邮件里的一次性 token 设置新密码（匿名，不需要登录）

#### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| token | string | 是 | 邮件链接里的 `token` 参数 |
| newPassword | string | 是 | 6–32 位，字母/数字/下划线至少含两种 |

```JSON
{ "token": "…", "newPassword": "newpass123" }
```

#### 响应数据

`data` 为 `null`。

#### 备注说明

> token 不存在、已用过、已过期，统一返回 `code=400 链接已失效，请重新申请`。
> 成功后 `token_version + 1`：**所有旧 token（含其他设备）立即失效**，必须用新密码重新登录。
> 前端页面路径：`/reset-password?token=…`（`APP_BASE_URL` 拼出来就是它）。

## 用户管理

三个接口都只作用于「当前登录用户」，**不接受客户端传 userId**（后端从 token 取）。

### 修改资料

#### 基本信息

请求路径：`/api/users/me`

请求方式：`PUT`

接口描述：改用户名（显示名）/ 登录邮箱；**改邮箱必须带当前密码**

#### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| username | string | 是 | 显示名：≤20 位，字符不限 |
| email | string | **是** | 登录凭据：≤100 字，需符合邮箱格式；与当前值不同时必须带 password |
| password | string | 条件 | 仅当改邮箱时必填，用于校验当前密码；只改用户名可省略 |

```JSON
{ "username": "生活委员", "email": "life@example.com", "password": "改邮箱时才填" }
```

#### 响应数据

返回更新后的用户信息，字段同注册接口的 `data`。

#### 备注说明

> 只改传了的字段；邮箱**不发验证邮件**，仅作展示（PLAN §9 第 2 条）。

### 修改密码

#### 基本信息

请求路径：`/api/users/me/password`

请求方式：`PUT`

接口描述：校验旧密码后修改密码，**并让所有已签发的 token 立即失效**

#### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| oldPassword | string | 是 | 旧密码，错误返回 `code=400 旧密码不正确` |
| newPassword | string | 是 | 6–32 位，字母/数字/下划线至少含两种 |

#### 响应数据

`data` 为 `null`。

#### 备注说明

> 成功后 `user.token_version + 1`，**旧 token 立刻返回真实 HTTP 401**，前端必须清 token 回登录页。
> 忘记密码不走这个接口，见「重置密码（命令行）」。

### 注销账户

#### 基本信息

请求路径：`/api/users/me`

请求方式：`DELETE`

接口描述：密码确认后**立即物理删除**账号及其名下全部数据（不进回收站）

#### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| password | string | 是 | 当前密码，错误返回 `code=400 密码不正确`，什么都不删 |

```JSON
{ "password": "******" }
```

#### 响应数据

`data` 为 `null`。

#### 备注说明

> 注销后账号**立即无法登录**，旧 token 返回 `code=401`；用户名与邮箱同时释放（可以重新注册）。
> 删除范围：user / book / category / transaction / password_reset_token —— **立即、彻底、不可恢复**。
> 想留档请在注销前导出 CSV 或做一次数据库备份。

## 账本

一个用户可以有多本账本（上限 10 本），**同一时刻只有一本是「当前账本」**（`user.current_book_id`）。
分类、流水、统计、导出全部只作用于当前账本——前端切换账本后必须重新拉这些数据。

账本信息随登录响应的 `books` 数组返回，也可以单独查列表。删除是**进回收站**：
15 天内可恢复，到期（每天 3:30）连同该账本的分类与流水彻底删除。

### 账本列表

#### 基本信息

请求路径：`/api/books`

请求方式：`GET`

接口描述：查询我的账本（不含回收站），按创建顺序

#### 请求参数

无

#### 响应数据

| 字段 | 类型 | 说明 |
|---|---|---|
| data[].id | number | 账本 id |
| data[].name | string | 账本名 |
| data[].type | string | 固定 `class` |
| data[].shareToken | string \| null | 当前公示链接 token；从未分享过为 `null`，链接 3 天有效 |
| data[].shareTokenExpiresAt | string \| null | 链接到期时间 `yyyy-MM-dd HH:mm:ss` |
| data[].categoryTemplateId | number \| null | 当前分类来自哪套自定义模板；`null` = 内置「班级班费」 |
| data[].semesterEnd | string \| null | 学期截止日期 `yyyy-MM-dd`；`null` = 没填。只用于展示，不参与统计 |
| data[].archived | boolean | 学期归档：`true` = 只读（不能记流水 / 不能改分类，但仍可改名、改截止日期、取消归档、导出、公示） |
| data[].current | boolean | 是否当前账本 |

```JSON
{
  "code": 200,
  "message": "success",
  "data": [
    { "id": 1, "name": "计科2301班费", "type": "class", "shareToken": null, "shareTokenExpiresAt": null, "categoryTemplateId": null, "semesterEnd": "2027-01-15", "archived": false, "current": true },
    { "id": 2, "name": "2025 秋季（已归档）", "type": "class", "shareToken": "9ac3…", "shareTokenExpiresAt": "2026-11-09 01:22:31", "categoryTemplateId": 7, "semesterEnd": "2026-01-15", "archived": true, "current": false }
  ]
}
```

#### 备注说明

> 访问列表时会顺手清理回收站里满 15 天的账本，所以响应里不会出现已过期未清理的数据。

### 新建账本

#### 基本信息

请求路径：`/api/books`

请求方式：`POST`

接口描述：新建一本账本，按所选**分类模板**事务内预置它的分类（默认内置「班级班费」11 条），并**自动切换为当前账本**

#### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| name | string | 是 | ≤50 字，不能全空格 |
| templateId | number \| null | 否 | 用哪套分类模板：**省略 / `0` / `null` = 内置「班级班费」**；自建模板 id 取自 `GET /api/category-templates`，别人的模板返回 `404 模板不存在` |
| semesterEnd | string \| null | 否 | 学期截止日期 `yyyy-MM-dd`；只是提示，不影响统计 |

```JSON
{ "name": "2026-2027 秋季", "templateId": 7, "semesterEnd": "2027-01-15" }
```

#### 响应数据

返回新建的账本（`current` 为 `true`），字段同「账本列表」；`categoryTemplateId` 即所选模板（内置为 `null`）。

#### 备注说明

> 每用户最多 10 本，超出返回 `400 账本最多 10 本，先删掉不用的`。
> 新建账本**不发**公示链接：`shareToken` 为 `null`，要点「分享」调 `POST /api/books/{id}/share` 才生成。
> 建好之后想换模板只能走 `POST /api/category-templates/{id}/apply`，且要求那本账本**还没有流水**——所以模板要在新建时一次选对。

### 修改账本（改名 + 学期截止日期）

#### 基本信息

请求路径：`/api/books/{id}`

请求方式：`PUT`

接口描述：修改自己账本的名字，可选同时改学期截止日期（公示页标题会跟着变，`shareToken` 不变）

#### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | number | 是 | 账本 id |
| name | string | 是 | 新账本名，≤50 字，不能全空格 |
| semesterEnd | string \| null | 否 | 学期截止日期 `yyyy-MM-dd`；**省略 / `null` = 保持原值**（不是清空） |

#### 响应数据

返回更新后的账本（字段同「账本列表」）。

#### 备注说明

> 改别人的账本返回 `404 账本不存在`（不区分「id 不存在」与「不是你的」）。
> 改名**不会**更换 `shareToken`，已经发到班群的公示链接继续有效（前提是那张链接还没过期）。
> **归档的账本仍然可以调这个接口**：改名与改截止日期属于「管理动作」，不在只读范围内。

### 归档 / 取消归档（学期结束 ↔ 重新开启）

#### 基本信息

请求路径：`/api/books/{id}/archive`（归档）、`/api/books/{id}/unarchive`（取消归档）

请求方式：`PUT`

接口描述：把一个学期记满的账本变成**只读**，换届后数据不会被误改；需要补记时随时取消

#### 请求参数

### 分享（一条链接带多本账本）/ 批量删除

#### 基本信息

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/books/share` | 生成**一条**公示链接，包含选中的全部账本 `{ids:[1,2]}` → `{token, expiresAt, books:[{id,name}]}` |
| POST | `/api/books/batch-delete` | 批量移入回收站 → 返回**剩余账本列表**（可能已换当前账本） |
| POST | `/api/books/batch-purge` | 批量彻底删除回收站里的账本 → 返回删除本数 |

#### 请求参数

```JSON
{ "ids": [1, 2] }
```

> `ids` 必填、去重后最多 200 条。

#### 备注说明

> **一条链接 = 选中的全部账本**：公开页 `/report/{token}` 一次返回这几本的数据，前端用标签页切换。
> **每次分享都换新 token**，旧链接立即失效（泄漏时再点一次「分享」就能掐掉它）。
> 单本分享仍可用 `POST /api/books/{id}/share`，等价于「只选了一本」。
> **批量删除要么全成功、要么整批拒绝**：选中里只要有一本不归自己，整批 404；删到一本不剩时整批 400。
> 删除当前账本会自动切到剩下最早的一本；批量彻底删除同样整批校验，任一条不在回收站就整批 404。
> 账本被彻底删除后会自动从链接里移除；链接里的账本全被删光时，链接整条 404。

## 分类

分类按**当前账本**隔离。注册时预置 11 条班级模板分类（没有「其他」，见下文说明），用户可以自由增删改。

> 「其他」不是预置分类：它只是「记一笔」分类下拉末尾的一个入口，选中就弹窗现建分类（可挑图标/颜色）。
> 所以模板与预置分类里都没有「其他」这一条。

`icon` / `color` 存的是**语义 key**（如 `supplies` / `orange`），前端自己映射图标组件与主题色；对未知 key 必须做兜底（默认图标、默认色）。

前端入口：独立的**分类管理页** `/categories`（侧栏「🏷 分类」，按支出/收入分组、改名、换图标颜色、删除）；「记一笔」弹窗内也能「＋ 新建分类」就地新建并选中。增删改后前端必须重拉分类列表，否则「记一笔」下拉与流水页筛选还是旧数据。

`type` **创建后不可修改**（改了会让该分类下历史流水的收支方向失真），`PUT` 传了不同的 `type` 后端返回 400。

同一账本、**同一收支方向**下分类名不能重复（新增和改名都会拦，`400` + `同类下已有同名分类「xxx」`）；不同方向可以同名。

`sort_order` 由后端在新增时自增写入，前端不支持拖拽排序。

## 分类模板

模板是**一整套分类清单**，跟**账号**走（不按账本隔离）：一套模板可以套用到该用户的任意账本，所以两本账本可以共用同一套「秋季学期」分类。

和「分类」的区别：

| | 分类（`/api/categories`） | 模板（`/api/category-templates`） |
|---|---|---|
| 归属 | 当前**账本** | **账号** |
| 数量 | 一本账本一套 | 一个账号多套 |
| 作用 | 记账时选它 | **新建账本时**选一套，用来预置那本账本的分类 |

内置模板「班级班费」（11 条，与注册时预置的分类完全一致，没有「其他」）**不入库**，`id` 固定为 `0`，不能改名删除。

「其他」不是分类也不是模板条目：它只是「记一笔」下拉末尾的虚拟入口，选中就弹窗现建分类。

## 流水

流水按当前账本隔离。金额一律 `BigDecimal`（库中 `DECIMAL(12,2)`），接口中序列化为两位小数的字符串。

一条不变量：**支出不能超过当前余额**（当前余额 = Σ收入 − Σ支出）。

### 导出班费收支表（CSV / Excel）

#### 基本信息

请求路径：`/api/transactions/export`

请求方式：`GET`

接口描述：该接口用于导出换届交接 / 发班群用的收支表，含逐行结余与分类合计。
`format=xlsx` 时是**真正的 Excel**：顶部收支汇总 + 并排的柱状图（收入/支出/结余）与环形图（收支占比）+ 明细

#### 请求参数

参数格式：`queryString`

参数说明：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| startDate | string | 否 | 起始日期（含），`yyyy-MM-dd`；不传表示不限 |
| endDate | string | 否 | 结束日期（含），`yyyy-MM-dd`；不传表示不限 |
| format | string | 否 | `csv`（默认）或 `xlsx`；xlsx 为单个 sheet「收支明细」，含并排的柱状图 + 环形图 |

请求数据样例：

```
/api/transactions/export?startDate=2026-10-01&endDate=2026-10-31&format=xlsx
```

#### 响应数据

参数格式：`text/csv`（**文件流，不是 JSON 信封**；服务端逐行流式输出，几千条流水也不会先在内存里攒整份文件）

响应头：

```
Content-Type: text/csv;charset=UTF-8
Content-Disposition: attachment; filename="=?UTF-8?Q?...?="; filename*=UTF-8''%E7%8F%AD...
```

文件内容样例（UTF-8 BOM + CRLF 换行）：

```TEXT
班级账本 收支明细
账本名,班级账本
导出时间,2026-11-08 10:30:00
统计区间,全部
期间收入,1900.00
期间支出,706.50
期初结余,0.00
期末结余,1193.50

日期,分类,摘要,收入,支出,结余
2026-09-05,收取班费,全班 38 人 × 50,1900.00,,1900.00
2026-10-12,聚餐,中秋聚餐,,620.00,1280.00
2026-11-08,班会物资,横幅+气球,,86.50,1193.50
合计,,,1900.00,706.50,1193.50

分类合计
分类,类型,金额
聚餐,支出,620.00
班会物资,支出,86.50
收取班费,收入,1900.00
```

#### 备注说明

> 成功时返回文件；**参数错误仍是 HTTP 200 + JSON 信封**（例如开始日期晚于结束日期 → `{"code":400,"message":"开始日期不能晚于结束日期"}`）。前端必须按响应类型分流：`responseType: 'blob'`，拿到 blob 后再判断是不是 JSON 错误。
> 期初结余 = 截至「起始日期前一天」的累计余额；期末结余 = 截至「结束日期」的累计余额。不传起始日期时期初为 `0.00`。
> 金额固定两位小数、日期为 `yyyy-MM-dd` 文本、UTF-8 BOM——Excel 双击打开中文不乱码。
> 备注里含逗号或引号时会按 CSV 规则加引号（`"横幅,气球"`），这是 Excel 能正确分列的前提。
> 文件名形如 `班费流水_全部.csv` / `班费流水_20261001-20261031.csv`；`format=xlsx` 时后缀为 `.xlsx`。
> **xlsx 的结构**（对齐真实班费表）：sheet「收支明细」顶部左侧是 `收入 / 支出 / 结余`
> 三行彩色汇总（A:B 标签 + C 金额），右侧 D..G 列里**柱状图（收入/支出/结余）与
> 环形图（收支占比）并排一行、各占一半宽度**，整个头部与表格同宽、左对齐；配色与网页端一致：
> 收入绿 / 支出红 / 结余蓝。第 13 行是单行表头 `序号 | 日期 | 摘要 | 收入 | 支出 | 班费结余 | 备注`，第 14 行起是明细。
> 图表数据放在同表隐藏的 J/K 列（不是隐藏 sheet）。
> **文件名**：`{账本名}_全部.xlsx`；带日期区间时是 `{账本名}_部分_{起始}-{结束}.xlsx`
> （CSV 同名，只是后缀不同）。

### 导入流水（CSV）

#### 基本信息

请求路径：`/api/transactions/import`

请求方式：`POST`（`multipart/form-data`）

接口描述：按「日期, 类型, 分类, 金额, 备注」批量导入流水，**行级失败不阻塞其它行**

#### 请求参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| file | file | 是 | **只支持 `.csv`**（Excel 请先另存为 CSV UTF-8），≤5MB、≤2000 行；含 BOM 也认 |

```CSV
日期,类型,分类,金额,备注
2026-09-05,收入,收取班费,1900.00,全班 38 人 × 50
2026-09-20,支出,聚餐,620.00,中秋聚餐
```

#### 响应数据

| 字段 | 类型 | 说明 |
|---|---|---|
| data.success | number | 成功写入的条数 |
| data.failed | array | 失败明细 |
| data.failed[].line | number | 文件行号（1 基，含表头，和 Excel 左侧一致） |
| data.failed[].reason | string | 失败原因 |

```JSON
{
  "code": 200,
  "message": "success",
  "data": {
    "success": 2,
    "failed": [{ "line": 4, "reason": "分类「不存在的分类」不存在（支出方向），请先在分类页建好再导入" }]
  }
}
```

#### 备注说明

> 类型接受「收入 / 支出」或 `income / expense`；日期必须是 `yyyy-MM-dd`；
> 金额范围 **0.01 ~ 999,999.99**、最多两位小数（超范围的行进 `failed`，原因里直接写出合法区间）。
> **分类不存在直接报错，不会自动创建**（一份脏文件不该在账本里长出一堆脏分类）。
> 支出仍受余额约束：按文件顺序累加余额，入不敷出的那一行失败。
> 归档账本只读，导入会返回 `400 当前账本已归档（学期结束）…`。
> 空文件 / 只有表头 / 超过 2000 行：整份拒绝，返回 `400`。
> **只收 CSV**：Excel 版式千人千面（合并单元格、数量/单价分组表头），上传 `.xlsx` 直接返回
> `400 导入只支持 CSV 文件；请在 Excel 里「另存为 → CSV UTF-8（逗号分隔）」后再上传`。
> **表头不用在第一行**：导入会扫描找「日期」开头的那一行，前面的标题/汇总会被跳过；
> 同时兼容本系统导出的 CSV 明细格式「日期, 分类, 摘要, 收入, 支出, 结余」（按收入/支出哪列有值判断方向），
> 所以「导出 CSV → 导入」可以原样转回去（相当于换账号/备份恢复）。

```JSON
{
  "success": 3,
  "failed": [{ "line": 12, "reason": "分类「聚餐」不存在（支出方向），请先在分类页建好再导入" }],
  "receipts": { "success": 5, "failed": [{ "file": "2026-09/坏图.png", "reason": "只支持 jpg / png / webp 图片" }] }
}
```

> 处理顺序：**先导流水 CSV 再挂图**（反过来的话，只有支出票据、收入在 CSV 里的包会因余额不足失败）。
> 挂图按「日期 + 类型 + 分类 + 金额 + 备注」匹配；完全相同的一笔重复出现时按顺序分配。
> manifest 里有、CSV 里没有的流水会在这里补建（兼容只有票据的包）。
> 分类不存在 → 该行失败，它名下的图片也计入票据失败；**不会自动建分类**。

### 单笔票据打包导入

`POST /api/transactions/{transactionId}/receipts/import`（multipart，`.zip`）

包里放这一笔的多张图片（可以都在一个子文件夹里），逐张导入，失败文件带相对路径与原因返回。
标题取文件名去扩展名；`__MACOSX/`、`.DS_Store` 自动跳过。

## 票据（小票/收据照片）

一笔流水可以挂最多 **9 张**票据照片（jpg / png / webp，单张 ≤5MB，账号总量 ≤500MB）。
磁盘按 `{账本名}_{bookId}/{yyyy-MM}/{uuid}.{ext}` 分层（月份取流水的 **业务日期**），
库里只存相对路径；账本改名不搬目录。**归档账本只读**：能看能导出，不能上传/删除。

### 上传票据

#### 基本信息

请求路径：`/api/transactions/{transactionId}/receipts`

请求方式：`POST`（`multipart/form-data`）

接口描述：给某一笔流水加一张票据。多选时前端逐张调用（一次一张，某张失败不影响其他张）。

#### 请求参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| transactionId | number | 是 | 路径参数，流水 id（必须属于当前账本） |
| file | file | 是 | 图片文件；**按魔数判断类型**，改扩展名骗不过，SVG 直接拒 |
| title | string | 否 | 票据标题 ≤30 字；不传则取文件名去扩展名（`.jpg` 这种没名字的回落「票据」） |

#### 响应数据

```json
{ "code": 200, "message": "success", "data": { "id": 12, "title": "超市小票", "originalName": "IMG_0001.png", "sizeBytes": 204800, "createdAt": "2026-11-10 15:20:00" } }
```

> 4xx 都是 `code=400/404` 的 JSON 信封：非图片「只支持 jpg / png / webp 图片」、
> 超 5MB「单张票据不能超过 5MB」、第 10 张「单笔最多 9 张票据」、越权统一 404「流水不存在」。

### 票据列表

`GET /api/transactions/{transactionId}/receipts` → `data` 是数组，元素同上（**不含文件内容、不含磁盘路径**）。

> 流水列表的每一项都带 `receiptCount`，前端徽标用它，不用每行再查一次。

### 预览 / 下载单张

`GET /api/transactions/{transactionId}/receipts/{receiptId}`

返回图片字节（`Content-Type: image/jpeg|png|webp`、`Content-Disposition: inline`、
`X-Content-Type-Options: nosniff`、`Cache-Control: private, max-age=300`）。
**登录态接口不能用 `<img src>` 直链**，前端要 `fetch` 成 blob 再转 objectURL。

### 改标题 / 删除

| 方法 | 路径 | 请求体 |
|---|---|---|
| PUT | `/api/transactions/{transactionId}/receipts/{receiptId}` | `{ "title": "班服收据" }`（1–30 字，空值 400） |
| DELETE | `/api/transactions/{transactionId}/receipts/{receiptId}` | 无（库里记录与磁盘文件一起删） |

### 导出票据

| 场景 | 方式 | 说明 |
|---|---|---|
| 整个账本（可带日期区间） | `GET /api/transactions/receipts/export?startDate&endDate` | 打包 zip，文件名 `{账本名}_票据_全部.zip` / `{账本名}_票据_部分_{起}-{止}.zip` |
| 单笔 | **前端下载图片**（`GET .../receipts/{id}` 逐张） | 不打包：单笔通常 1–3 张，直接存成 `{日期}_{标题}.{ext}` 更直观 |

> 单笔的 zip 接口已下线，`GET /api/transactions/{transactionId}/receipts/export` 不再存在。

zip 内部（与磁盘同构，解开就能对上 `data/receipts`）：

```
{账本名}_{bookId}/2026-11/2026-11-05_超市小票.png
manifest.csv     ← 日期,类型,分类,金额,备注,票据标题,相对路径（UTF-8 BOM）
```

> 同目录标题重名自动加 `_2`、`_3`；一次最多 200 张 / 100MB，超了 400「请缩小日期范围」。
> 没有票据时也是 `200 + code=400` 的 JSON 信封（不是空 zip），前端按响应类型分流。

## 统计

统计口径与公示页共用同一套实现，数字必须与公示页一致。

`month` 参数：不传按**当月**（北京时间）统计；必须是 `yyyy-MM`，格式错（如 `2026-8`、`2026-13`）返回 `400 月份格式应为 yyyy-MM，例如 2026-08`，**不会**静默返回空数据。

### 月度汇总

#### 基本信息

请求路径：`/api/statistics/summary`

请求方式：`GET`

接口描述：该接口用于查询某月的收入、支出、结余，以及全账本累计余额

#### 请求参数

参数格式：`queryString`

参数说明：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| month | string | 否 | `yyyy-MM`；不传取当月 |

请求数据样例：

```
/api/statistics/summary?month=2026-10
```

#### 响应数据

参数格式：`application/json`

参数说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| data.month | string | 实际统计的月份（回显，不传时后端补当月） |
| data.income | string | 本月收入合计 |

### 公示页票据图片（免登录）

#### 基本信息

请求路径：`/api/public/report/{shareToken}/receipts/{receiptId}`

请求方式：`GET`（**不需要** `Authorization`）

接口描述：返回票据图片字节，供公示页的缩略图/大图直接用 `<img src>`。
这条路径挂在 `/api/public/report/**` 白名单下，`SecurityConfig` 不用再加规则。

#### 响应

图片字节：`Content-Type: image/jpeg|image/png|image/webp`、
`Content-Disposition: inline`、`X-Content-Type-Options: nosniff`、
`Cache-Control: private, max-age=300`。

#### 校验（四条缺一不可，任一不满足都 404，不返回 403/400 暴露「存在但无权」）

1. `shareToken` 存在且未过期（与公示页正文同一个判断）；
2. 票据所属流水的账本在链接覆盖的账本里；
3. 该流水未删除（进回收站后公示页也看不到它的票据）；
4. 该账本未被注销/删除。

> 响应里**没有**原始文件名、磁盘路径、流水 id、上传者；也没有任何匿名上传/删除/改名/导出的入口。

## 附录

### A. 错误码总表

| code | 含义 | 典型场景 |
|---|---|---|
| 200 | 成功 | — |
| 400 | 参数错误 / 业务错误 | 参数校验失败、用户名已存在、密码错误、余额不足、分类类型不可改、删除有流水的分类、月份格式错 |
| 401 | 未登录或 token 失效 | 未带 token、token 过期、账号已注销 |
| 403 | 无权访问 | 已登录但无权限（当前版本无角色，正常业务不会出现） |
| 404 | 资源不存在 | 分类/流水不存在、公示 token 无效、接口路径不存在 |
| 500 | 服务器异常 | 未预期异常，此时应查看后端 `logs/*-error.log` |

### B. 注册预置的 11 条分类

| 类型 | 分类名（icon / color） |
|---|---|
| 支出（7） | 班会物资（supplies/orange）、活动经费（activity/purple）、聚餐（dining/red）、打印复印（print/cyan）、场地（venue/green）、交通（transport/blue）、奖品（prize/yellow） |
| 收入（4） | 收取班费（fee/green）、学院拨款（subsidy/blue）、活动赞助（sponsor/purple）、结余转入（carryover/cyan） |

「结余转入」是给换届用的：新生活委员建账后第一笔记「上学期结余 X 元」，历史衔接就清晰了。

**没有「其他」**：它只是「记一笔」分类下拉末尾的虚拟入口，选中就弹窗现建分类（可挑图标与颜色），所以不需要预置这一条。

### C. 常见联调问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 金额显示 `620.00` 但计算后出现 `620.0000000001` | 前端把字符串 `parseFloat` 后累加 | 保持字符串，或用 decimal 库计算 |
| 请求返回 200 但页面没数据 | 业务错误也是 HTTP 200，只读了 data 没看 code | 拦截器统一判断 `code !== 200` 后提示 `message` |
| 刷新页面跳登录 | token 只存在内存 | 存 localStorage，启动时用 `/api/auth/me` 校验 |
| 导出点下载得到一堆 JSON | 用 `responseType: 'text'` 或没判断错误 | 设 `responseType: 'blob'`，blob 以 `{` 开头时按 JSON 解析错误 |
| 表格里同一天多笔顺序乱 | 只按日期排序 | 后端已按 `trans_date DESC, id DESC`，前端不要重新排序 |
| 用别人账号的数据能查到 | 传了 `book_id` 或复用了旧 token | 不要传 book_id；换账号时清 token 重新登录 |
