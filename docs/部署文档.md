# 部署操作步骤

服务器：`81.71.140.152`（Debian 13 + Docker）。按顺序执行，每步都给了预期结果。

用普通用户 `wsj` 登录（需要时 `sudo`）；`docker compose` 都在 `/opt/bookkeep-server/docker` 下执行，除 `down`/备份重定向等少数命令外一律加 `sudo`。

## 1. 安全组

腾讯云控制台 → 安全组 → 入站规则，加两条：

| 协议 | 端口 | 来源 |
|---|---|---|
| TCP | 22 | 你的 IP |
| TCP | 80 | 0.0.0.0/0 |

不要加 3306 / 8080 / 443。

## 2. 本地打包

```powershell
cd D:\coding\bookkeep-server
mvn -pl bookkeep-web -am -DskipTests clean package

cd D:\coding\bookkeep-web
npm run build
```

把产物放成这个结构再压缩（或直接用 `deploy\upload\bookkeep-cloud.zip`，同目录还有可单独替换的 `bookkeep.jar` / `bookkeep-dist.zip`）：

```
bookkeep-server/
  docker/                  docker-compose.yml / Dockerfile / nginx.conf / .env
  bookkeep-web/target/bookkeep.jar
  bookkeep-web/dist/
  sql/schema.sql
```

## 3. 上传

```powershell
scp D:\coding\bookkeep-server\deploy\upload\bookkeep-cloud.zip wsj@81.71.140.152:/home/wsj/
```

## 4. 解压

```bash
sudo unzip -q /home/wsj/bookkeep-cloud.zip -d /opt
cd /opt/bookkeep-server/docker
```

预期：`/opt/bookkeep-server`、`/opt/README.md` 存在。

## 5. 改配置

```bash
vi .env
```

只改这两处：

```bash
APP_BASE_URL=http://81.71.140.152

# 要用「找回密码」才填，否则留空
MAIL_USERNAME=
MAIL_PASSWORD=
MAIL_FROM=
```

`MYSQL_ROOT_PASSWORD` / `DB_PWD` / `JWT_SECRET` 已生成，不要改。

## 6. 启动

```bash
sudo docker compose up -d --build
sudo docker compose ps
```

预期：`mysql` 是 `healthy`，`app` 和 `nginx` 是 `Up`。首次约 2–5 分钟。

## 7. 验证

```bash
curl -I http://127.0.0.1/
sudo docker compose exec -T mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -N -e "show tables" bookkeep' | wc -l
sudo docker compose logs --tail=20 app
```

预期：

- `HTTP/1.1 200 OK`
- 表数量 `10`
- 日志有 `启动成功 ... 端口: 8080 环境: prod`

浏览器打开 `http://81.71.140.152/`，注册 → 记一笔 → 传票据 → 分享，看能否正常。

## 8. 连数据库（可选）

```bash
cd /opt/bookkeep-server/docker
sudo docker compose exec mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" bookkeep'
```

Navicat：本机执行 `ssh -L 3307:127.0.0.1:3306 wsj@81.71.140.152`，再连 `127.0.0.1:3307`。

## 9. 备份

```bash
cd /opt/bookkeep-server/docker
sudo docker compose exec -T mysql sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --default-character-set=utf8mb4 bookkeep' > ~/backup-$(date +%F).sql
sudo docker compose exec -T app tar czf - -C /app/data receipts > ~/receipts-$(date +%F).tgz
```

重定向是 `wsj` 自己写的，所以落到 `~`（`/opt` 需要 root，别往那写）。

恢复：

```bash
cd /opt/bookkeep-server/docker
sudo docker compose exec -T mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" bookkeep' < ~/backup-2026-11-10.sql
sudo docker compose cp ~/receipts-2026-11-10.tgz app:/tmp/
sudo docker compose exec app tar xzf /tmp/receipts-2026-11-10.tgz -C /app/data
```

## 10. 停止 / 重启

```bash
sudo docker compose restart app     # 只重启进程，不重新读 .env
sudo docker compose up -d app       # 改完 .env 必须用这个（重建容器才带新环境变量）
sudo docker compose down            # 停（数据保留）
sudo docker compose down -v         # 连数据一起删，别用
```

## 11. 日常更新

几类改动，处理方式不同：

| 改了什么 | 要做的事 | 为什么 |
|---|---|---|
| 只改前端 | 覆盖 `bookkeep-web/dist` + `chown` | dist 是 bind mount，nginx 立刻读到新文件，不用重启 |
| 后端 jar | 换 jar → `sudo docker compose up -d --build app` | jar 打进镜像，`restart` 换不掉 |
| `.env`（`JWT_SECRET` / `JWT_EXPIRE` / 邮件） | `sudo docker compose up -d app` | `restart` 不重新读环境变量 |
| 新增 `sql/migration_*.sql` | 见下面第三条命令 | 建表脚本只在空数据卷执行一次 |

前端（`bookkeep-dist.zip` 已传到 `/home/wsj/`）：

```bash
cd /opt/bookkeep-server
sudo unzip -o /home/wsj/bookkeep-dist.zip -d bookkeep-web/dist
sudo chown -R wsj:wsj bookkeep-web/dist
```

后端（`bookkeep.jar` 已传到 `/home/wsj/`）：

```bash
cd /opt/bookkeep-server
sudo cp /home/wsj/bookkeep.jar bookkeep-web/target/bookkeep.jar
cd docker
sudo docker compose up -d --build app
sudo docker compose logs --tail=20 app     # 预期：启动成功 ... 环境: prod
```

数据库结构变更（每个 `migration_*.sql` 只跑一次）：

```bash
cd /opt/bookkeep-server
sudo docker compose -f docker/docker-compose.yml exec -T mysql \
  sh -c 'mysql --default-character-set=utf8mb4 -uroot -p"$MYSQL_ROOT_PASSWORD" bookkeep' \
  < sql/migration_xxx.sql
```

`JWT_SECRET` 换掉等于让所有已签发的 token 失效（全员重新登录）；`JWT_EXPIRE` 改了同样要 `up -d` 才生效。
