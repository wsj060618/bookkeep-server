# 部署文档（云端 Docker Compose）

一台公网服务器跑 `mysql + app + nginx` 三个容器，浏览器访问 `http://<服务器IP>/`。
本地开发用的是 `deploy/` 那套 Windows 直跑方案，两套互不影响。

```
浏览器 ──▶ nginx:80 ──▶ app:8080 ──▶ mysql:3306
              │             │             │
         frontend dist   bookkeep.jar   db_data 卷
                                      receipts_data 卷（票据图片）
```

对外只开 **80**（SSH 另算）。3306 只绑服务器回环，8080 完全不 publish。

## 1. 前置

- 服务器：2C2G 起，Debian/Ubuntu + Docker（当前试用机：Debian 13 + Docker 29，腾讯云，`81.71.140.152`）
- 域名：**不需要**。没备案的域名在国内会被拦，裸 IP 也签不到可信证书，所以就是 `http://IP/`
- 安全组：只放 **22**（限自己 IP）和 **80**；不要放 3306 / 8080 / 443

> 没有 HTTPS 是有意的。补偿：登录限流、JWT 有效期 1 天、3306 只绑回环、只开 80。
> **别在这个环境里用常用密码。**

## 2. 生成部署包（本机）

服务器上不需要 JDK / Maven / MySQL，只需要 Docker。所以 jar 和前端必须在本地构建好再上传。

```powershell
# 后端
cd D:\coding\bookkeep-server
mvn -pl bookkeep-web -am -DskipTests clean package      # → bookkeep-web/target/bookkeep.jar
# 前端（另一个仓库）
cd D:\coding\bookkeep-web
npm run build                                           # → dist
```

包内目录结构必须是这样（compose 里用相对路径引用）：

```
bookkeep-server/
  docker/                 docker-compose.yml / Dockerfile / nginx.conf / .env
  bookkeep-web/target/bookkeep.jar
  bookkeep-web/dist/      前端产物
  sql/schema.sql          首次启动自动建表
README.md
```

> 打包时 zip 条目分隔符必须是 `/`。用 .NET 的 `CreateFromDirectory` 打出来是 `\`，
> Linux 上 `unzip` 会解出一堆带反斜杠的文件名——要么在 Linux 上 `zip -r`，要么手工构造条目。

cd /opt

## 4. 配置 `.env`

`docker/.env` 与 `docker-compose.yml` 同级（compose 只认这一处），改完不用重新 build，`up -d` 生效。

| 变量 | 说明 |
|---|---|
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码，**只在数据卷为空时生效** |
| `DB_PWD` | 应用账号 `bookkeep` 的密码（compose 会自动建这个账号） |
| `JWT_SECRET` | ≥32 字符随机串；prod 下是仓库默认值会**拒绝启动** |
| `JWT_EXPIRE` | 秒，默认 `86400`（1 天） |
| `MAIL_USERNAME` / `MAIL_PASSWORD` / `MAIL_FROM` / `MAIL_FROM_NAME` | QQ 邮箱 SMTP；不填则「找回密码」返回成功但不发信 |
| `APP_BASE_URL` | 公网地址，如 `http://81.71.140.152`（找回密码邮件里的链接用它） |
| `NGINX_CONF` | 默认 `./nginx.conf`（纯 HTTP）；有备案域名才换 `./nginx.tls.conf` |

模板见 `docker/.env.example`。

## 5. 启动

```bash
docker compose up -d --build
docker compose ps
```

首次启动会：拉镜像 → 构建 app 镜像 → 建库 → 执行 `sql/schema.sql`（10 张表）→ 起后端 → 起 nginx。
**只有 `db_data` 卷为空时才会建表**，之后重启不会覆盖数据。

`book`、`category`、`category_template`、`category_template_item`、`password_reset_token`、

## 7. 连数据库

MySQL 只绑 `127.0.0.1:3306`，公网进不来。

```bash
cd /opt/bookkeep-server/docker
# 交互式
docker compose exec mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" bookkeep'
# 一条 SQL
docker compose exec -T mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "select count(*) from bookkeep.book"'
```

`$MYSQL_ROOT_PASSWORD` 是容器内环境变量，所以要 `sh -c` 包一层；`-T` 关掉伪终端便于脚本。

Navicat / DBeaver：本机开隧道，把服务器回环的 3306 映射到本地 3307。

```powershell
ssh -L 3307:127.0.0.1:3306 root@81.71.140.152
```

客户端连 `127.0.0.1:3307`，用户 `bookkeep`，密码 `.env` 里的 `DB_PWD`。

> 改 `.env` 的 `MYSQL_ROOT_PASSWORD` 对已有库**无效**（只在初始化时用），
> 要改密码得进库 `ALTER USER 'root'@'%' IDENTIFIED BY '新密码';`。

## 8. 把本地数据搬上去

本地库 dump（Windows）：

```powershell
& "D:\Program Files\MySQL\MySQL Server 8.4\bin\mysqldump.exe" -uroot -p `
  --default-character-set=utf8mb4 --single-transaction --databases bookkeep `
  > D:\coding\bookkeep-server\deploy\bookkeep-data.sql
```

导入服务器（目标库已存在，所以是 `mysql bookkeep <`，不是整库覆盖）：

```bash
docker compose exec -T mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" bookkeep' < /opt/bookkeep-data.sql
```

票据图片（本地 `deploy/data/receipts`）：

```powershell
tar -czf D:\coding\bookkeep-server\deploy\receipts.tgz -C D:\coding\bookkeep-server\deploy\data receipts
scp D:\coding\bookkeep-server\deploy\receipts.tgz root@81.71.140.152:/opt/
```

```bash
docker compose cp /opt/receipts.tgz app:/tmp/
docker compose exec app tar xzf /tmp/receipts.tgz -C /app/data
```

> 数据库和图片必须一起搬：只搬库，页面有记录但图全裂。

## 9. 备份与恢复

```bash
# 数据库
docker compose exec -T mysql sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --default-character-set=utf8mb4 bookkeep' > /opt/backup-$(date +%F).sql

# 票据图片（在命名卷里，必须单独备份）
docker compose exec -T app tar czf - -C /app/data receipts > /opt/receipts-$(date +%F).tgz
```

恢复：

```bash
docker compose exec -T mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" bookkeep' < /opt/backup-2026-11-10.sql
docker compose cp /opt/receipts-2026-11-10.tgz app:/tmp/
docker compose exec app tar xzf /tmp/receipts-2026-11-10.tgz -C /app/data
```

**恢复演练**要真正做过一次：dump → 删一行 → 恢复 → 行数复原 → 页面能看。

## 10. 日常

```bash
docker compose logs -f app        # 应用日志
docker compose restart app        # 改完 .env
docker compose down               # 停（数据卷保留）
docker compose down -v            # ⚠️ 连数据一起删，别手滑
docker compose ps                 # 状态
docker volume inspect bookkeep_db_data   # 数据卷在宿主机的位置
```

## 11. 排错

| 现象 | 原因 / 处理 |
|---|---|
| `docker compose up` 卡在拉镜像 | 国内常见。配腾讯云加速：<br>`cat > /etc/docker/daemon.json <<'EOF'`<br>`{ "registry-mirrors": ["https://mirror.ccs.tencentyun.com"] }`<br>`EOF`<br>`systemctl daemon-reload && systemctl restart docker` |
| 报 `MYSQL_ROOT_PASSWORD is required` 之类 | `.env` 不在 `docker/` 目录，或变量没填 |
| app 起不来，日志说 jwt | `JWT_SECRET` 还是默认值 / 不足 32 字符 |
| 访问是 502 | app 没起来：`docker compose logs app` |
| 上传票据 413 | nginx 的 `client_max_body_size`（已设 12m）被外层代理改小 |
| 公示页 404 | 链接过期（3 天）或被新分享替换 |
| 找回密码收不到信 | `MAIL_*` 没填 / QQ 授权码过期（看 app 日志有没有 SMTP 报错） |
| 表格中文乱码 | 手工执行 SQL 时忘了 `--default-character-set=utf8mb4` |

## 12. 安全清单

- [ ] 安全组只开 22（限 IP）+ 80
- [ ] `ss -lntp | grep -E '3306|8080'` 只看到 `127.0.0.1:3306`，没有 8080
- [ ] `JWT_SECRET` 随机且 ≥32 字符
- [ ] `DB_USER` 是 `bookkeep`，不是 root
- [ ] 登录限流生效（连错 5 次被拒）
- [ ] Nginx 透传 `X-Real-IP`（`docker/nginx.conf` 已配）
- [ ] 备份能恢复到新库，票据包也能恢复
- [ ] 明文 HTTP 已确认接受（没有域名 → 没有 TLS，密码与 JWT 在公网上是明文）

## 13. 已知限制

- 限流是**单实例内存**计数，多副本部署会各算各的（本项目单机）
- 服务器到期数据就没了：试用期结束前把 dump + 票据包拉回本地
- 没有 HTTPS：微信/QQ 里点裸 IP 链接可能提示风险，属正常现象
